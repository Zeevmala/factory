# Voice

How prose that an agent writes for you should read: READMEs, pull request descriptions, design docs, commit messages, issue comments.

## Rules

- 2026-11-15: Lead with the answer or the change. Context comes after, and only as much as the reader needs.
- 2026-11-15: Short by default. Expand on architecture and trade-offs, nowhere else.
- 2026-11-15: Write for an expert in GIS and spatial data. Do not explain what a CRS, a tile or a GeoJSON feature is.
- 2026-11-15: State what was measured, with the command and its output. Never "should work".
- 2026-11-15: One idea per sentence. Plain verbs. No marketing tone.

## Words and patterns never to use

- 2026-11-15: "seamless", "robust", "leverage", "cutting-edge", "game-changer", "delve", "unlock", "empower", "blazing fast".
- 2026-11-15: Openers that praise the question or the code. Closers that offer more help.
- 2026-11-15: Emoji in headings or commit messages.
